## 3. 결함 목록 (심각도순)

### [상] 아바타 링 색상이 브랜드 액션색과 완전히 동일
- **어디**: `02-home-scroll.png`의 크루 소식 피드 — "쫀"(쫀쫀샷) 아바타 링. 코드는 `app/src/components/avatar.tsx:27`.
- **왜 결함인가**: CLAUDE.md 디자인 전역 규칙 "블루 솔리드(현재 포레스트그린) = 액션 전용, 정보 블록엔 쓰지 않는다"를 위반. `RINGS = [Brand.brand, Team.red, Team.green]`에서 이름 해시가 `Brand.brand`를 고르면, 아바타 링(정보성 장식)이 "러닝 시작" 버튼(액션)과 픽셀 단위로 동일한 초록이 된다. 실측: 링 `RGB(47,110,74)`, CTA 버튼 `RGB(47,110,74)` — 완전 일치. 사용자가 무의식적으로 탭 가능 요소로 오인할 수 있고, "액션 신호는 하나뿐"이라는 프로젝트 핵심 규칙의 유일성이 깨진다.
- **수정 방안**: `RINGS` 배열에서 `Brand.brand`를 제거하고, 액션색과 색상각 30° 이상 떨어진 제3의 뉴트럴(예: 잉크 톤을 낮춘 브라운 계열 또는 새 무채색 계열)로 교체. `Team.green`도 함께 재설계 대상(아래 4번 참조)이므로 두 건을 한 번에 처리하는 게 효율적.

### [중] 랭킹 격차 문구 ↔ 화면 숫자 산술 불일치
- **어디**: `shots/r18-ranking.png`·`r18/06-ranking.png` — "이번 주 2위예요. **1위와 1.8km 차이**예요." 그런데 화면의 1위(쫀쫀샷) = 16.4km, 본인(쭌쭌) = 14.5km. 16.4−14.5 = **1.9**.
- **왜 결함인가**: `app/src/app/ranking.tsx:41`의 `gapKm = Math.abs(ranking[myRank-1].km - rival.km)`는 반올림 전 원시 값으로 계산하고, 114·158행의 화면 표시값은 각 순위별로 독립적으로 `.toFixed(1)` 처리된다. 두 반올림이 서로 다른 소수 자리에서 이뤄지다 보니 "화면에 보이는 두 숫자를 암산하면 문구와 어긋나는" 경우가 생긴다(예: 원시값 16.35/14.55 → 표시 16.4/14.5, 원시 차 1.80 → 반올림 1.8, 그러나 표시값끼리 빼면 1.9). CLAUDE.md의 "숫자는 예외 없이 신뢰할 수 있어야 한다"는 취지에서 벗어난다 — 사용자가 직접 계산해보고 앱을 못 믿게 되는 유형의 결함. R10 시절 코드(이번 라운드 신규 아님)지만 실데이터로 처음 드러났다.
- **수정 방안**: `gapKm`을 화면에 실제로 보이는 반올림값 기준으로 재계산(`Math.abs(round(km1,1) - round(km2,1))`)하거나, 문구를 "약 1.8km 차이"로 완충 표현.

## 4. 줄간격(`leading()`) 변경 검증

- **적용 범위**: `grep -rn "leading("` = 144건(정의부 1건 제외 143건 실사용) — 커밋 주장과 일치.
- **제외 판단**: 입력칸(`TextInput`) 9곳에 `leading()`이 붙은 사례 없음(스팟체크 통과) — 안드로이드 TextInput+lineHeight 잘림 이슈를 피한 판단은 타당.
- **단위·배지·칩·버튼라벨·큰숫자 42곳 제외**: 단일 행 텍스트에 줄간격을 줘도 시각 효과가 없고 박스만 커진다는 근거(`leading()` 함수 주석)는 RN 렌더링 특성상 합리적. 캡처에서 실제로 단위(`km`·`회`) 옆 여백이 과도하게 벌어진 사례는 발견되지 않음.
- **첫 뷰포트 잘림 여부**: `01-home.png`(요약+CTA+워치버튼+챌린지카드+피드 시작까지 한 화면), `03-crew.png`, `04-run.png`, `06-ranking.png`(=`r18-ranking.png` 기준), `08-my.png` 전부 하단 탭바 위로 콘텐츠가 자연스럽게 이어지고 문장 중간에 잘리는 곳 없음. **줄간격 변경으로 인한 첫 뷰포트 회귀는 없다** — 이 변경의 유일한 리스크였던 항목은 통과.
- **총평**: 실행은 꼼꼼했다(전수 검색 후 예외 처리, tsc 통과, 실기기 8캡처 무회귀). 다만 이 변경 자체가 "타이포" 축의 위험을 관리한 것이지 점수를 크게 올리는 종류의 작업은 아니다 — 이미 13/15 근처였던 축의 잔여 리스크를 없앤 정도로 평가한다.

## 5. 95점까지 남은 것

1. **아바타 링 색 재설계** (`avatar.tsx:27`) — `Brand.brand`를 `RINGS`에서 빼고 `Team.green`도 함께 브랜드 그린과 색상각 30°+ 벌어지는 새 색으로 교체. 이 한 건이 "브랜드 일관성"과 "색·대비" 두 축에 걸쳐 있어 고치면 가장 효율적으로 점수가 오른다.
2. **랭킹 gapKm 계산을 표시값 기준으로 통일** — `ranking.tsx:41`. 사용자가 암산해도 안 틀리게.
3. **캡처 절차에 "최상단 리셋" 단계 추가** — 이번처럼 라벨과 다른 내용의 캡처가 검증 없이 통과되는 걸 원천 차단.
4. **밀린 숙제(⬜, `docs/DESIGN.md` "앱 디자인 큐")**: 공유 카드, 페이스+고도 결합 차트, 다크 모드 — 여전히 미구현. 95점을 넘어 그 다음 단계로 가려면 결국 이 항목들이다.
5. **웹 실배포 + 서비스명 통일** — 지금은 파일만 바뀌었고 라이브는 구 팔레트·구 이름("모두의 마라톤")이다. 완성 선언 전 반드시 정리.

위 1·2번을 고치면 정직하게 **95/100**을 줄 수 있다고 본다 — 새로 나온 두 결함이 사라지면 이번에 검증된 팔레트·타이포의 실질적 진전만 남기 때문이다.
