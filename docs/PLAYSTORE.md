## 테스터 12명 — 실제로 굴러가게 하는 법

1. **구글 그룹을 하나 만든다**(예: `5kilo-testers@googlegroups.com`). 이메일을 한 명씩
   콘솔에 넣는 것보다 관리가 쉽다 — 사람이 바뀌어도 그룹만 고치면 된다.
2. 크루원에게 **구글 계정 이메일**을 받는다(플레이스토어에 로그인한 그 계정이어야 한다).
3. 콘솔 → 비공개 테스트 트랙 → 테스터에 그룹 주소 등록 → **옵트인 링크**를 단톡방에 뿌린다.

5. **14일 동안 지우지 말아 달라고 미리 말해 둔다.** 이게 카운트의 핵심이고, 중간에 빠지면
   그 사람 몫이 리셋된다.

⚠️ 12명은 **최소치**다. 중간 이탈을 감안해 **15명 이상** 모으는 편이 안전하다.

## 1) AAB 빌드

플레이스토어는 APK가 아니라 **AAB**(Android App Bundle)를 받는다.

```bash
cd app
# prebuild는 로컬 APK 스크립트와 동일하게 선행돼야 한다
npx expo prebuild --platform android --clean
cd android && ./gradlew bundleRelease
# → android/app/build/outputs/bundle/release/app-release.aab
```

⚠️ **서명키 주의.** 지금 `app/credentials/local-release.jks`로 서명하는데, 이 키를 **업로드 키**로
등록하고 **Play App Signing**(구글이 최종 서명키를 보관)을 켜는 것이 안전하다. Play App Signing
없이 이 키가 최종 서명키가 되면, **키를 잃는 순간 앱 업데이트가 영원히 불가능**해진다.
`local-release.jks`는 gitignore돼 있으므로 별도 백업이 필수다.

### ⚠️ "다른 사용자에게 표시됨" 체크를 빠뜨리지 말 것 (2026-08-01 정정)

데이터 안전 양식에는 항목마다 **"이 데이터가 앱 내에서 다른 사용자에게 표시될 수 있습니까"**를
묻는 칸이 있다. 우리 앱은 **크루가 서로의 기록을 보는 것이 서비스의 본질**이라 아래 항목이
전부 여기에 해당한다 — 빠뜨리면 실제 동작과 신고가 어긋난다.

| 항목 | 다른 사용자에게 표시 | 어디에 |
|---|---|---|
| 러너 네임 | **O** | 전 화면 |
| 러닝 거리·시간·페이스 | **O** | 러닝 목록·상세·랭킹·홈 |
| 평균 심박 | **O** | 러닝 목록·상세 |
| 프로필 사진 | **O** | 이름이 나오는 모든 자리(아바타) |
| 갤러리 사진·방명록 | **O** | 크루 탭 |
| 이메일 | X | 저장만, 화면에 안 띄운다 |

**이 표는 2026-08-01 기준으로 `firestore.rules`가 8개 컬렉션 전부 `read: if true`인 상태를
반영한 것이다.** 크루 격리(`docs/BRIEF.md`)가 적용되면 노출 범위가 "앱을 깐 전원" → "같은 크루"로
좁아지므로, **적용 시 이 표와 처리방침 §6을 함께 개정한다.**

## 4) 권한 정당화 (심사에서 물어본다)

- ~~`ACCESS_BACKGROUND_LOCATION`~~ — **2026-08-01 제거했다.** 선언은 돼 있었지만 실제 백그라운드
  추적은 미구현이었고(“화면을 켜 둔 채로 달려주세요” 안내 중), 코드도 포그라운드 권한만
  요청하고 있었다. 없는 기능으로 심사에서 정당화·시연 영상을 요구받는 건 소명이 불가능하다.
  → `app.json`의 permissions 배열과 `expo-location` 플러그인의
  `isAndroidBackgroundLocationEnabled` **양쪽 모두** 꺼야 매니페스트에서 빠진다(한쪽만 끄면 남는다).
  나중에 화면 꺼짐 대응을 구현할 때 다시 켜고, 그때 시연 영상을 준비한다.
- `FOREGROUND_SERVICE` / `FOREGROUND_SERVICE_LOCATION` — 유지. 러닝 추적에 정당한 권한이고
  백그라운드 위치보다 심사 문턱이 훨씬 낮다.
- `health.READ_*`(Health Connect) — 갤럭시워치 러닝 불러오기. Health Connect 정책상 별도 선언 필요.

### ⚠️ 우리가 선언하지 않은 권한이 AAB에 들어간다 (2026-08-01 발견)
`app.json`의 `permissions` 배열은 **추가**만 한다. 라이브러리들이 자기 매니페스트에 넣은 권한은
그대로 **병합**되어 최종 AAB에 실린다. 실제로 첫 AAB를 뜯어보니 이런 것들이 있었다:

| 권한 | 출처 | 판정 |
|---|---|---|
| **RECORD_AUDIO**(마이크) | 라이브러리 병합 | ❌ 안 쓴다. 민감 권한이라 데이터 안전 양식과 불일치 + 사용자 불신 |
| **SYSTEM_ALERT_WINDOW** | react-native | ❌ 안 쓴다. 정책상 별도 정당화 요구 |
| **CAMERA** | expo-image-picker | ❌ 우리는 `launchImageLibraryAsync`(갤러리)만 쓴다 |
| **RECEIVE_BOOT_COMPLETED** | 라이브러리 병합 | ❌ 부팅 시 실행하지 않는다 |
| READ/WRITE_EXTERNAL_STORAGE | expo-image-picker (`maxSdkVersion=32`) | ✅ 유지 — 안드로이드 12 이하에서 갤러리 접근에 필요 |
| WAKE_LOCK · VIBRATE · ACCESS_NETWORK_STATE | 라이브러리 | ✅ 유지 — 무해하고 정당 |

→ `android.blockedPermissions`로 앞의 4개를 차단했다(`tools:node="remove"`가 붙어 병합 단계에서
빠진다). **소스 매니페스트에는 그대로 보이므로 반드시 병합 결과로 확인할 것**:
```bash
cd android && ./gradlew processReleaseManifest
grep -oE 'android:name="android.permission[^"]*"' \
  app/build/intermediates/merged_manifests/release/processReleaseManifest/AndroidManifest.xml | sort -u
```
새 라이브러리를 넣을 때마다 이 확인을 다시 할 것 — 조용히 권한이 늘어난다.

## 4-1) 스크린샷은 언제 찍나

지금 앱에는 데이터가 거의 없다(테스트 데이터는 검증 후 매번 지웠다). 빈 화면을 찍어 올리면
스토어에서 "쓸 게 없는 앱"으로 보인다. **비공개 테스트 14일 동안 크루의 실제 기록·사진·랭킹이
쌓이므로, 그때 찍는 것이 훨씬 설득력 있다.**

찍을 화면 (폰 세로, 2~8장):
1. 홈 — 크루 타임라인에 사람들 기록이 흐르는 모습
2. 러닝 시작 — GPS 지도(2026-08-01에 또렷하게 개선한 화면)
3. 러닝 완료 요약 — 경로 지도 + 거리
4. 공유 카드 — 지도가 들어간 카드
5. 랭킹 — 시상대에 크루원 이름이 찬 모습
6. 크루 — 사진 그리드
7. 마이 — 배지·프로필

⚠️ 스크린샷에 **다른 사람의 실명·얼굴이 나오면 동의를 받아야 한다.** 크루원 이름이 그대로
보이므로, 테스터에게 미리 양해를 구하거나 닉네임 상태에서 찍을 것.

## 6) iOS는 어디까지 와 있나

**코드는 이미 준비돼 있다** — Expo 한 코드베이스라 iOS 빌드 자체는 명령 한 줄이다.
막혀 있는 건 코드가 아니라 **계정·기기**다.

| 필요한 것 | 상태 |
|---|---|
| Apple Developer Program **$99/년** | ⬜ 미등록 (안드로이드 $25와 별개, 매년 갱신) |
| Mac | **불필요** — EAS 클라우드가 macOS 빌더를 제공한다 |
| 아이폰 실기기 | ⬜ 테스트폰이 갤럭시라 확인 불가 |
| TestFlight 배포 | ⬜ $99 등록 후 가능(최대 10,000명, 링크 배포) |
| **HealthKit**(애플워치) | ⬜ 미구현 — Health Connect(갤럭시)만 붙어 있다 |
| iOS 아이콘·스플래시 자산 | ⚠️ `assets/expo.icon` 번들에 **Expo 기본 로고가 남아 있다**(2026-07-30 발견) |

**지금 iOS를 미루는 게 맞는 이유**: 안드로이드 비공개 테스트 14일이 도는 동안 크루의 실사용
피드백이 쌓인다. 그걸 반영한 뒤 iOS로 넘어가는 편이, 두 스토어에서 같은 버그를 두 번 겪는 것보다
낫다. iOS를 먼저 하려면 $99 + 아이폰 실기기 확보가 선행돼야 한다.
