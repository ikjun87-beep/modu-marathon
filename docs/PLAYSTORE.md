## 테스터 12명 — 실제로 굴러가게 하는 법

1. **구글 그룹을 하나 만든다**(예: `5kilo-testers@googlegroups.com`). 이메일을 한 명씩
   콘솔에 넣는 것보다 관리가 쉽다 — 사람이 바뀌어도 그룹만 고치면 된다.
2. 크루원에게 **구글 계정 이메일**을 받는다(플레이스토어에 로그인한 그 계정이어야 한다).
3. 콘솔 → 비공개 테스트 트랙 → 테스터에 그룹 주소 등록 → **옵트인 링크**를 단톡방에 뿌린다.
4. 각자 링크를 눌러 참여 → 플레이스토어에서 정상 설치.
5. **14일 동안 지우지 말아 달라고 미리 말해 둔다.** 이게 카운트의 핵심이고, 중간에 빠지면
   그 사람 몫이 리셋된다.

⚠️ 12명은 **최소치**다. 중간 이탈을 감안해 **15명 이상** 모으는 편이 안전하다.

## 1) AAB 빌드

플레이스토어는 APK가 아니라 **AAB**(Android App Bundle)를 받는다.

```bash
cd app
# prebuild는 로컬 APK 스크립트와 동일하게 선행돼야 한다
npx expo prebuild --platform android --clean
cd android && ./gradlew bundleRelease
# → android/app/build/outputs/bundle/release/app-release.aab
```

⚠️ **서명키 주의.** 지금 `app/credentials/local-release.jks`로 서명하는데, 이 키를 **업로드 키**로
등록하고 **Play App Signing**(구글이 최종 서명키를 보관)을 켜는 것이 안전하다. Play App Signing
없이 이 키가 최종 서명키가 되면, **키를 잃는 순간 앱 업데이트가 영원히 불가능**해진다.
`local-release.jks`는 gitignore돼 있으므로 별도 백업이 필수다.

## 4) 권한 정당화 (심사에서 물어본다)

- `ACCESS_BACKGROUND_LOCATION` — **러닝 앱의 핵심 기능**: 화면을 끄거나 다른 앱을 봐도 경로가
  끊기지 않아야 한다. 심사 제출 시 이 설명 + 시연 영상이 요구될 수 있다.
  ⚠️ 지금은 실제로 백그라운드 추적을 구현하지 않았다(“화면을 켜 둔 채로 달려주세요” 안내 중).
  **구현 전이라면 이 권한을 매니페스트에서 빼는 편이 심사가 쉽다.**
- `health.READ_*`(Health Connect) — 갤럭시워치 러닝 불러오기. Health Connect 정책상 별도 선언 필요.

## 6) iOS는 어디까지 와 있나

**코드는 이미 준비돼 있다** — Expo 한 코드베이스라 iOS 빌드 자체는 명령 한 줄이다.
막혀 있는 건 코드가 아니라 **계정·기기**다.

| 필요한 것 | 상태 |
|---|---|
| Apple Developer Program **$99/년** | ⬜ 미등록 (안드로이드 $25와 별개, 매년 갱신) |
| Mac | **불필요** — EAS 클라우드가 macOS 빌더를 제공한다 |
| 아이폰 실기기 | ⬜ 테스트폰이 갤럭시라 확인 불가 |
| TestFlight 배포 | ⬜ $99 등록 후 가능(최대 10,000명, 링크 배포) |
| **HealthKit**(애플워치) | ⬜ 미구현 — Health Connect(갤럭시)만 붙어 있다 |
| iOS 아이콘·스플래시 자산 | ⚠️ `assets/expo.icon` 번들에 **Expo 기본 로고가 남아 있다**(2026-07-30 발견) |

**지금 iOS를 미루는 게 맞는 이유**: 안드로이드 비공개 테스트 14일이 도는 동안 크루의 실사용
피드백이 쌓인다. 그걸 반영한 뒤 iOS로 넘어가는 편이, 두 스토어에서 같은 버그를 두 번 겪는 것보다
낫다. iOS를 먼저 하려면 $99 + 아이폰 실기기 확보가 선행돼야 한다.
