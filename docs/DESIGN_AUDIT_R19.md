**단, 두 가지는 이번 커밋의 주장을 그대로 믿을 수 없었다 — 코드를 직접 추적해 확인:**

- **`ringTier`(성장 링)의 tier 3은 여전히 `Brand.brand`를 쓴다** — 아래 결함 목록 참조. 이번 커밋 범위에서 명시적으로 제외됐다.

**판정: 이번에 채점 대상이었던 RINGS 배열(이름-해시 아바타 전원, 즉 크루·랭킹·댓글·홈 피드에 등장하는 '남의' 아바타 전체)의 액션색 충돌은 완전히, 검증 가능하게 해소됐다.**

### ② 시상대 격차가 화면 숫자와 안 맞던 것 — **고쳐짐 (검증 완료)**

`ranking.tsx:46-48`: `r1(v) = Math.round(v*10)/10` 로 먼저 반올림한 뒤 빼도록 변경. `04-ranking-top-podium.png` 실측:
- 1위(쫀쫀샷) 화면 표시 `16.4km`, 나(쭌쭌) 화면 표시 `14.5km`
- 안내 문구: **"1위와 1.9km 차이예요"**
- 검산: 16.4 − 14.5 = **1.9** — 문구와 정확히 일치.

R18이 잡았던 "16.4−14.5=1.9인데 문구는 1.8"이라던 어긋남이 이번엔 없다. 코드도 `r.km.toFixed(1)`(표시)과 `r1()`(격차 계산)이 **같은 반올림 자릿수**를 쓰도록 통일돼 있어, 이 화면 조합에서만 우연히 맞은 게 아니라 구조적으로 항상 맞게 되어 있다.

**판정: 완전히 고쳐졌다.**

## 4. 남은 결함 (심각도순)

### [중] `ringTier`의 tier 3이 여전히 `Brand.brand`(액션색)를 쓴다
- **어디**: `app/src/components/avatar.tsx:99` — `else if (tier === 3) { color = Brand.brand; ... }`. 화면은 `my.tsx:203`(프로필 히어로, 획득 배지 3~4개일 때만 발현 — 이번 시딩 데이터는 획득 2개라 이번 캡처엔 안 보임, 코드로 확인).
- **왜 결함인가**: 바로 이 커밋이 "링에 브랜드색·골드를 쓰지 말 것"이라고 못 박은 규칙을, **같은 파일 안에서 6줄 아래(line 99)가 어긴다.** 더 나쁜 건 위치다 — `my.tsx:475`의 `heroCam`(사진 변경 카메라 아이콘, 진짜 액션 버튼)도 `backgroundColor: Brand.brand`이고, 이 카메라 배지는 아바타 링 위에 **겹쳐서(`right:-2, bottom:-2`)** 그려진다. 즉 배지 3~4개를 딴 사용자는 성장 링(정보)과 카메라 버튼(액션)이 **같은 초록으로 맞닿아 하나의 덩어리**로 보인다 — 이번에 고친 RINGS 문제와 정확히 같은 유형의 위반이 다른 트리거 조건으로 남아 있는 것.
- **심각도가 [상]이 아니라 [중]인 이유**: 발현 범위가 좁다(내 프로필 히어로 아바타 1개, 배지 3~4개 구간에서만). RINGS 문제(화면 전체의 '남의 아바타' 전원)보다 노출 빈도·범위가 훨씬 작다.

### [하] `teamColorOf` 기반 "내 아바타" 링이 36px 미만에서는 마스코트 없이 이니셜만 그려 근거가 사라진다
- **어디**: `avatar.tsx:106`(`drawFace = me && size >= 36`) + 실사용처 `index.tsx:278`(size 30)·`ranking.tsx:143`(size 34).

## 5. 다음 라운드 권고

**디자인 축에서 점수를 더 올릴 여지는 크지 않다.** 95점에서 남은 항목은 전부 좁은 범위·낮은 빈도의 잔여 이슈이지 새로운 축의 개선이 아니다. 우선순위:

1. **`ringTier` tier 3 색 교체** (`avatar.tsx:99`) — 한 줄 수준의 수정이고, 고치면 "링에 액션색·골드 쓰지 않는다"는 규칙이 파일 전체에서 예외 없이 성립한다. R18→R19처럼 "지적하면 바로 다음 라운드에 고쳐지는" 낮은 비용 항목이므로 R20에서 가장 먼저 처리 권장.
2. **캡처 스크립트에 "섹션 헤더 기준 스크롤 정지" 규칙 추가** — `11`류의 경계 캡처를 원천 차단.
3. **`docs/DESIGN.md` "앱 디자인 큐"의 밀린 숙제**(공유 카드, 페이스+고도 결합 차트, 다크 모드)는 R18에서도 지적됐고 여전히 미착수 — 96점 이상을 노린다면 결국 이 항목들이지, 지금 있는 잔여 색상 이슈를 더 파도 소용이 적다.
4. **디자인은 이쯤에서 유지 모드로 전환하고, 다른 축(기능·품질)에 자원을 옮기는 것을 권장한다.** tier 3 한 줄만 고치고 나면, 이번 세션이 반복해온 "채점→지적→수정→재채점" 루프에서 디자인 쪽은 수익 체감 구간에 들어섰다 — 앱 스토어 출시 준비(`docs/BUILD.md`)·워치 연동 검증 등 실행 트랙으로 무게중심을 옮길 시점이다.
